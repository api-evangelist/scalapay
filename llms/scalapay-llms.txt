## API Reference
- [API Architecture](https://developers.scalapay.com/reference/api-architecture.md)
- [Payment Flows](https://developers.scalapay.com/reference/payment-flows-1.md): Scalapay offers two flexible payment capture options to suit your business needs: *Immediate Payment Flow* for instant settlement and *Delayed Payment Flow* for deferred capture. This guide explains both to help you choose the right fit for your operations.
- [Webhooks](https://developers.scalapay.com/reference/webhooks.md)
- [Listener authentication setup](https://developers.scalapay.com/reference/listener-authentication-setup.md)
- [Webhook data model](https://developers.scalapay.com/reference/wehook-data-model.md)
- [Messages validation](https://developers.scalapay.com/reference/messages-validation.md)
- [Examples of webhook requests](https://developers.scalapay.com/reference/examples-of-webhook-requests.md)
- [Connection issues and retry system](https://developers.scalapay.com/reference/connection-issues-and-retry-system.md)
- [PHP SDK](https://developers.scalapay.com/reference/php-sdk.md): Here is our PHP SDK that will simplify your journey of integrating with us.
- [API Simulator](https://developers.scalapay.com/reference/api-simulator.md)
- [Status page](https://developers.scalapay.com/reference/api-authentication-copy.md)
- [Overview](https://developers.scalapay.com/reference/overview-3.md)
- [Create order](https://developers.scalapay.com/reference/post_v2-orders.md): Create a Scalapay order. The endpoint returns a `token` required to capture the payment and a `checkoutUrl` that redirects the customer to Scalapay Checkout, where the payment is authorized.
- [Update order](https://developers.scalapay.com/reference/post_v2-orders-token.md): Update an order by changing the `merchantReference`. Use this endpoint when specifying the `merchantReference` during order creation was not possible.
- [Get order details](https://developers.scalapay.com/reference/get_v2-payments-token.md): Return all details regarding the specified order.
- [Get orders by reference](https://developers.scalapay.com/reference/get_v2-payments-references.md): Retrieve a list of order references based on one or more known reference values. At least one query parameter must be provided. Multiple parameters are combined with AND logic.  The endpoint returns a maximum of 100 matching orders, sorted by creation date (newest first).
- [Delay order](https://developers.scalapay.com/reference/post_v2-payments-token-delay.md): Request a delayed capture for the order. The payment schedule for the customer is created; however, no funds are settled until a capture call is made. Outstanding authorizations are automatically voided once the authorization expiry time is reached.
- [Capture order](https://developers.scalapay.com/reference/post_v2-payments-capture.md): Capture the payment associated with the order. The specified amount is deducted from the user's account and transferred to the merchant's account. You can capture an amount up to the total specified during order creation. You may also provide an updated `merchantReference` to update the order.
- [Void order](https://developers.scalapay.com/reference/post_v2-payments-token-void.md): Void any authorizations for the order. The customer is informed of the cancellation and that the order could not be fulfilled; any held funds are released.
- [Overview](https://developers.scalapay.com/reference/overview-1.md)
- [Refund order](https://developers.scalapay.com/reference/post_v2-payments-token-refund.md): Refund a fulfilled payment. The funds are reversed from the merchant's account and returned to the customer.
- [Overview](https://developers.scalapay.com/reference/overview.md)
- [Create instore order](https://developers.scalapay.com/reference/post_v1-instore-orders.md): Create an instore order and charge the customer. Use the correct Bearer token for authentication.
- [Get an instore order](https://developers.scalapay.com/reference/get_v1-instore-orders-token.md): Retrieve the status of an instore order.
- [Get instore orders by reference](https://developers.scalapay.com/reference/get_v1-instore-orders-references.md): Retrieve a list of instore order references based on one or more known reference values. At least one query parameter must be provided. Multiple parameters are combined with AND logic.  The endpoint returns a maximum of 100 matching orders, sorted by creation date (newest first).
- [Refund an instore order](https://developers.scalapay.com/reference/post_v1-instore-orders-token-refund.md): Refund an instore order. The refund is processed and funds are transferred back to the customer.
- [Create an offline pay-by-link order](https://developers.scalapay.com/reference/post_v2-instore-paybylink-orders.md): Create an offline pay-by-link order and notify the customer using the extensions. Use the correct device Bearer token, not the merchant token.
- [Void an offline pay-by-link order](https://developers.scalapay.com/reference/post_v2-instore-paybylink-orders-token-void.md): Void the instore order, for example if a customer wishes to cancel. Any authorizations or held funds for the pay-by-link order are released.
- [Overview](https://developers.scalapay.com/reference/overview-2.md)
- [Get orders](https://developers.scalapay.com/reference/get_v1-reporting-orders.md): Retrieve orders. This endpoint enables merchants to reconcile bank transactions with orders and refunds within the Scalapay platform. Use the Scalapay API key Bearer token to access this endpoint.
- [Get refunds](https://developers.scalapay.com/reference/get_v1-reporting-refunds.md): Retrieve refunds. This endpoint enables merchants to reconcile bank transactions with orders and refunds within the Scalapay platform. Use the Scalapay API key Bearer token to access this endpoint.
- [Get payouts](https://developers.scalapay.com/reference/get_v1-reporting-payouts.md): Retrieve payouts. This endpoint provides a list of all payouts received from Scalapay. Use the Scalapay API key Bearer token to access this endpoint.
- [Get orders from payout](https://developers.scalapay.com/reference/get_v1-reporting-payouts-token-orders.md): Retrieve orders from a payout. This endpoint provides a list of orders associated with a specific payout. Use the Scalapay API key Bearer token to access this endpoint.
- [Get refunds from payout](https://developers.scalapay.com/reference/get_v1-reporting-payouts-token-refunds.md): Retrieve refunds from a payout. This endpoint provides a list of refunds associated with a specific payout. Use the Scalapay API key Bearer token to access this endpoint.
